# S03 — Lược đồ sản phẩm và logic biến thể

|              |                                   |
| ------------ | --------------------------------- |
| Trạng thái   | Đã chốt quyết định, chờ phê duyệt |
| Phụ thuộc    | S02                               |
| Bước kế tiếp | Chưa xếp, quyết định khi S03 xong |

## 1. Mục tiêu

Dựng lược đồ dữ liệu sản phẩm và logic sinh biến thể, kèm hạ tầng test chạy trên PostgreSQL
thật. Bước này **chưa có endpoint HTTP nào** — kiểm chứng bằng seed script và test tích hợp.

## 2. Kết quả bàn giao

### 2.1 Thực thể

```
Category ──< Product ──< ProductVariant >── Color
                    │              └────── Size
                    ├──< ProductImage
                    └──o SizeChart
```

Một thiết kế khai báo tập màu và tập size. Hệ thống sinh sẵn toàn bộ ma trận tổ hợp, admin
tắt những tổ hợp không sản xuất. Ba màu × năm size cho mười lăm biến thể; tắt hai tổ hợp
còn mười ba biến thể bán được.

### 2.2 Kiểm chứng

```bash
docker compose exec api sh -c "cd apps/api && pnpm exec prisma migrate deploy"
docker compose exec api sh -c "cd apps/api && pnpm exec prisma db seed"

docker compose exec db psql -U shopflow -d shopflow -c \
  "select sku, price, stock_quantity, is_active from product_variants order by sku"
# 15 dòng, trong đó 13 dòng is_active = true
```

### 2.3 Ba chỗ dễ làm sai

**Giá nằm ở biến thể, không nằm ở sản phẩm.** Size 2XL tốn nhiều vải hơn nên được phép có giá
khác. Đặt giá ở `Product` thì tới lúc cần giá riêng theo size phải sửa lược đồ và sửa mọi truy
vấn đã viết.

**Thứ tự size không phải thứ tự bảng chữ cái.** Sắp theo tên cho ra `2XL, L, M, S, XL`. Cần một
cột thứ tự tường minh, và mọi truy vấn trả danh sách size phải dùng nó.

**SKU không được đổi sau khi đã xuất hiện trong đơn hàng.** Ràng buộc R8. Nếu SKU sinh từ tên
sản phẩm thì đổi tên sản phẩm sẽ kéo theo nhu cầu đổi SKU — quyết định ở §5 phải tính tới điều này.

## 8. Ghi chú cho bước sau

- **Test tích hợp chạy hết 9,15 giây** kể cả thời gian dựng container, dưới xa ngưỡng 60 giây
  đặt ở §6. Một container dùng chung cho cả lần chạy, cô lập dữ liệu bằng `TRUNCATE` trước mỗi
  test. Các tệp test tích hợp phải chạy tuần tự vì dùng chung một database.
- **`CatalogService` đã có sẵn hai đường đọc**: `listSellableVariants` và `listPublishedProducts`.
  Bước làm API đọc cho khách dùng lại được, không phải viết từ đầu.
- **Seed chạy lại được nhiều lần**, bỏ qua thiết kế đã tồn tại. Dữ liệu mẫu cố ý có một tổ hợp
  bị tắt và một SKU hết hàng.
- **Vị trí API quản trị sản phẩm vẫn chưa quyết** (quyết định 3). Đây là việc đầu tiên phải chốt
  khi mở bước kế tiếp.
- **Thêm chiều biến thể thứ ba sau khi đã bán hàng là việc khó**, không phải một migration nhẹ:
  công thức SKU đổi kéo theo phải sinh lại SKU đang có, mà SKU thì không được đổi (ADR-006).
