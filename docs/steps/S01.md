## 1. Mục tiêu

Thiết lập cấu trúc monorepo, bộ công cụ phát triển và pipeline CI. Bước này không bao gồm logic nghiệp vụ.

## 2. Kết quả bàn giao

### 2.1 Cấu trúc thư mục

```
ecommerce-hands-on/
├── apps/
│   ├── api/                  NestJS — một route: GET /healthz
│   │   └── Dockerfile.dev
│   └── web/                  Vue 3 + Vite — một trang: gọi /api/healthz và hiển thị kết quả
│       └── Dockerfile.dev
├── packages/
│   └── shared/               Hàm formatVnd, xác nhận hai ứng dụng import được
├── docker-compose.yml        PostgreSQL 16 + api + web
├── .env.example              Giá trị mẫu; .env thật không commit
├── .nvmrc                    22
├── .github/workflows/ci.yml  lint → typecheck → test → build
└── package.json              pnpm workspace
```

### 2.2 Lệnh vận hành

```bash
cp .env.example .env              # điền mật khẩu database, DOCKER_UID, DOCKER_GID
pnpm install                      # cài trên host, phục vụ IDE và typecheck
docker compose up -d              # db :5432, api :3000, web :5173

curl localhost:5173/api/healthz
# {"status":"ok"}
```

Mã nguồn được bind mount vào container nên sửa file có hiệu lực ngay, không cần build lại image. Thư mục `node_modules` dùng volume riêng để bản cài trong container không bị bind mount của host ghi đè.

### 2.3 Đường đi của request

Ứng dụng web gọi API qua proxy của Vite tại đường dẫn `/api`, không gọi trực tiếp cổng `:3000`. Cấu hình này giữ cho môi trường phát triển và môi trường production cùng là same-origin, là điều kiện để cơ chế xác thực bằng cookie tại bước S05 hoạt động mà không cần cấu hình CORS.

Do web chạy trong container, đích của proxy là `http://api:3000` — tên service trong mạng nội bộ của Docker Compose — chứ không phải `http://localhost:3000`. Cấu hình `localhost` sẽ trỏ vào chính container web và luôn thất bại.

Vite phải chạy với `--host 0.0.0.0` để nhận kết nối từ ngoài container.

### 2.4 Khả năng chạy trên nền tảng khác

Toàn bộ runtime nằm trong container nên hệ điều hành của máy chủ không ảnh hưởng tới phiên bản Node hay PostgreSQL. Ba khác biệt còn lại được xử lý bằng cấu hình, không bằng sửa mã nguồn:

| Khác biệt                                                                               | Cách xử lý                                                                                                                |
| --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| macOS và Windows không phân biệt hoa thường trong tên tệp; container Linux và CI thì có | ESLint bật `import/no-unresolved` ở chế độ `caseSensitiveStrict`, chặn ngay khi commit thay vì để lỗi lộ ra ở CI          |
| Ký tự xuống dòng khác nhau giữa Windows và Linux                                        | `.gitattributes` với `* text=auto eol=lf`                                                                                 |
| Bind mount trên macOS và Windows không phát sinh sự kiện inotify đáng tin cậy           | Biến `WATCH_POLLING` trong `.env` điều khiển chế độ theo dõi tệp của Vite và NestJS. Mặc định tắt trên Linux, bật khi cần |

Quyền tệp: Docker Desktop trên macOS và Windows tự ánh xạ user, nhưng Docker chạy trực tiếp trên Linux thì không. Tài khoản trong WSL của máy này có `uid=1001`, trong khi user `node` của image `node:22-alpine` là `uid=1000` — lệch nhau sẽ khiến tệp do container tạo ra không sửa được từ máy chủ. Compose ánh xạ user qua `DOCKER_UID` và `DOCKER_GID` đọc từ `.env`, mỗi máy tự điền bằng `id -u` và `id -g`.

Ngoài ra, script trong `package.json` chỉ được gọi lệnh của công cụ hoặc script Node, không dùng cú pháp riêng của shell.

## 7. Ghi chú cho bước sau

- **Khoá ví dụ của AWS không kích hoạt cảnh báo.** `AKIAIOSFODNN7EXAMPLE` nằm trong tài liệu chính thức của AWS nên các công cụ quét bỏ qua có chủ đích. Khi kiểm chứng lại cổng chặn secret phải dùng chuỗi ngẫu nhiên, nếu không sẽ kết luận nhầm là cổng hỏng.
- **Đẩy tệp trong `.github/workflows/` cần scope `workflow`.** Token `gh` hiện tại chưa có. Chạy `gh auth refresh -h github.com -s workflow` — lệnh này mở trình duyệt nên phải tự chạy.
- **Cổng PostgreSQL đọc từ `POSTGRES_PORT`**, mặc định `5432`. S02 dùng giá trị này để dựng `DATABASE_URL`.
- **`packages/shared` xuất bản qua `dist`.** Chạy trong Docker thì service `shared` tự biên dịch lại khi mã đổi; chạy trực tiếp trên máy chủ thì phải `pnpm --filter @shopflow/shared build`.
- **Thời gian CI: 30 giây** ở lần chạy đầu (run 31620129106, chưa có cache). Ngưỡng cần chú ý là 5 phút, vượt thì xem lại quyết định về Turborepo — còn rất xa.
- **Đã nâng action lên major mới nhất** để hết cảnh báo Node.js 20 bị khai tử: `actions/checkout@v7`, `actions/setup-node@v7`, `pnpm/action-setup@v6`. Trước đó dùng `@v4` và bị GitHub ép chạy trên Node.js 24.
